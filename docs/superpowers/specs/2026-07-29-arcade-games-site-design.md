# Arcade: a GitHub Pages games site

Date: 2026-07-29
Status: approved, ready for implementation planning

## Purpose

Publish playable browser games at a public URL so colleagues can click and play,
starting with the IBM Safeguarded Copy Pac-Man game. The site carries an index of
games and a GitHub Actions workflow that regenerates that index whenever a game is
added, mirroring how `triippiing/Wiki` regenerates its runbook index.

## Success criteria

1. `https://triippiing.github.io/Arcade/` serves an index listing the SGC game.
2. Clicking the card loads the game and it plays correctly in a browser.
3. Adding a new game folder and pushing regenerates the index with no hand edits.
4. Another GitHub user can clone or fork the repo, enable Pages, and get a working
   site at their own `<user>.github.io/<anything>/` with no code changes.

## Constraints

**Static only.** GitHub Pages serves static files. No server, no database, no
build step beyond the Python script that Actions runs.

**Relative paths everywhere.** Every URL the site emits is relative
(`games/safeguarded-copy/`, `assets/css/arcade.css`, `../../`). Root-relative
paths such as `/Arcade/assets/...` are forbidden because they break under a
different repo name, under a root domain, and under `file://`. This constraint is
what makes success criterion 4 hold.

**Standard library only** in the builder, so it runs on macOS default Python 3 and
on `ubuntu-latest` with no dependency install.

**No em or en dashes** in any generated markup, code, comment, or copy.

## Decisions

| Question | Decision | Reasoning |
|---|---|---|
| Leaderboard | Keep localStorage, local per browser | No backend exists and none is wanted; a shared table needs a third party service, an API key in client JS, and fake score handling |
| Visual identity | Its own arcade identity, no shared assets with Wiki | Games are not runbooks; the Wiki's paper and ink theme would fight the content. The SGC game's own palette (deep navy, IBM Plex, cyan and green glow) is the starting point |
| Layout | Folder per game | Handles a single file game and one with sprites or audio equally; gives clean URLs like `/Arcade/games/safeguarded-copy/` |
| Card art | Screenshot with generated fallback | No cover art exists today; generated tiles mean a new game looks intentional immediately, and dropping in `cover.png` later upgrades the card with no code change |
| Game source of truth | The repo | Desktop editing has no history and reintroduces the drift problem `sync_source_blocks.py` exists to solve on the Wiki |
| Repo name | `Arcade` | Fits the cabinet select aesthetic; leaves the root user pages slot free |
| Categories | None | The Wiki's category dict earns its place across 21 runbooks in 9 folders. One game does not need taxonomy |

## The game contract

A game is any file matching `games/*/index.html`. Exactly one level of nesting:
`games/<slug>/index.html`. The slug is the URL segment and must be lowercase
kebab-case. Deeper paths such as `games/a/b/index.html` are not scanned.

Each game declares itself to the index through `<head>` meta tags:

| Tag | Purpose | Required | Default |
|---|---|---|---|
| `<title>` | Card title | yes | n/a |
| `<meta name="description">` | One line blurb on the card | yes | n/a |
| `<meta name="added" content="YYYY-MM-DD">` | Sort key and "new" badge | yes | n/a |
| `<meta name="keywords">` | Comma separated tags, rendered as chips | no | no chips |
| `<meta name="game-accent" content="#36e0c8">` | Card edge and fallback tile colour | no | house cyan `#36e0c8` |
| `<meta name="game-controls">` | e.g. `Arrows / WASD, swipe on mobile` | no | line omitted |

**Missing a required tag fails the build.** The builder exits non-zero with the
offending path named, and the workflow goes red. With this few games a loud
failure is more useful than a silently half-empty card. Optional tags falling back
to defaults never fail.

**Malformed values also fail**: `added` that is not a valid ISO date, `game-accent`
that is not a `#rrggbb` or `#rgb` hex value.

Cover art resolution, first match wins: `cover.png`, `cover.jpg`, `cover.webp` in
the game folder. If none is present the builder emits a generated tile: a flat
panel in the game's accent colour carrying the title's initials as a monogram,
written as inline SVG markup in the card.

## The builder

`scripts/build_index.py`, pure standard library, modelled on the Wiki's
`build_index.py` but substantially smaller: no sidebar nav data, no staleness
logic, no category ordering.

Behaviour:

1. Walk `games/*/index.html`, skipping nothing else in the repo.
2. Parse the meta tags above with regexes, in the same style as the Wiki builder.
3. Validate required and malformed values; collect every error, then exit non-zero
   reporting all of them at once rather than stopping at the first.
4. Resolve cover art or build a fallback tile.
5. Sort games by `added` descending, then title ascending as a tiebreak, so output
   is deterministic.
6. Render the card grid and write it into `index.html` between generated markers.

Generated markers: the card grid is delimited by
`<!-- BEGIN GENERATED GAMES -->` and `<!-- END GENERATED GAMES -->`. Everything
outside those markers in `index.html` is hand authored and preserved verbatim, so
the page header, footer, and any copy can be edited without the builder clobbering
it. If the markers are absent from `index.html`, the builder fails with a clear
message rather than guessing.

The builder never writes anywhere except `index.html`.

An empty `games/` directory is valid: the builder writes an empty grid and the
index renders an "no games yet" state from the hand authored side of the markers.

## The workflow

`.github/workflows/build-index.yml`, a near copy of the Wiki's:

- Triggers: push to `main` touching `games/**`, `scripts/build_index.py`, or the
  workflow file itself; plus `workflow_dispatch`.
- `permissions: contents: write`.
- Concurrency group `build-index`, cancel in progress.
- Skips itself when the head commit message contains `[skip ci]`.
- Runs `python3 scripts/build_index.py`, then commits `index.html` back with
  `[skip ci]` in the message if and only if it changed.

The commit back retriggers the Pages deployment, so adding a game is: drop the
folder in, push, done.

Because `index.html` is a committed real file, the site works even if the workflow
never runs. A clone with Actions disabled still serves correctly, it just will not
auto refresh when a game is added. This matters for the colleague fork case.

## Changes to the SGC game

1. Move `~/Desktop/sgc-leaderboard.html` to `games/safeguarded-copy/index.html`.
   The Desktop file stays in place as a backup until the live site is confirmed
   working, then it can be deleted.
2. Add the meta tags: `description`, `added`, `keywords`, `game-accent`
   (`#36e0c8`, the game's own `--data` colour), `game-controls`.
3. Add a back link in the game's chrome pointing at `../../` so a player can
   return to the index.
4. Everything else is untouched: the Google Fonts link stays, the localStorage
   leaderboard (`sgc-scores-v1`) stays, the engine is not modified.

The localStorage leaderboard is per browser and per origin. Scores on the live
site, on a colleague's fork, and on a local preview are all separate. That is a
consequence of the local only decision, not a defect.

## Index page

Full visual design is the next deliverable and is deliberately not specified here
beyond direction: dark, neon, cabinet select energy, IBM Plex, drawing on the SGC
game's palette. It does not reuse the Wiki's `tokens.css`, `sidebar.css`, or
`chrome.js`, and it does not repeat the Wiki's IPL boot sequence.

Structural requirements the design must satisfy:

- Responsive card grid, single column on narrow screens.
- Each card: cover or fallback tile, title, blurb, tag chips, controls line, and a
  play affordance linking to `games/<slug>/`.
- Generated markers as specified above.
- Relative paths only.

## Testing and verification

There is no test framework in this repo and none is being added. Verification is
manual and explicit:

1. Run `python3 scripts/build_index.py` locally and read the `index.html` diff.
2. Run it a second time and confirm the diff is empty, proving determinism.
3. Delete a required meta tag from a scratch copy and confirm the builder exits
   non-zero naming that file.
4. Serve locally via `serve.sh` and click through: index renders, card links to
   the game, game plays, back link returns to the index.
5. After the first push, confirm the live Pages URL renders and the game plays.

## Out of scope

Shared or remote leaderboard. Search or filtering on the index. Categories or
grouping. Per game analytics. Any second game. Migrating the Wiki. Custom domain.
